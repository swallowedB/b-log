이 사례는 이미 공개된 [COMMA 구현 기록](/posts/game-delta-time-fps-fix)을 이력서에서 찾아보기 쉽도록 정리한 것입니다.

## Problem
최종 QA에서 같은 게임이 팀원마다 다른 속도로 실행되었습니다. 고주사율 환경에서 더 빠르게 진행되어 난이도 편차가 발생했습니다.

## Context
COMMA의 게임 업데이트 로직에 관한 구현 기록입니다. 이 페이지는 원문이 설명하는 문제와 변경 범위를 요약하며 프로젝트 전체 기여도를 주장하지 않습니다.

## Analysis
오브젝트가 프레임마다 고정된 거리를 이동하면 업데이트 호출 횟수가 많은 환경에서 초당 이동 거리가 늘어납니다. 원문은 프레임 기반 이동량과 시간 기반 이동량을 비교합니다.

## Decision
이동 거리를 속도와 경과 시간의 곱으로 계산하도록 변경했습니다. 장비별 업데이트 횟수보다 실제 경과 시간을 기준으로 삼는 판단입니다.

## Action
requestAnimationFrame의 timestamp 또는 performance.now로 Delta Time을 계산하고 이동·속도 변화에 적용했습니다. 게임 종료 시 업데이트 취소 처리도 원문에 기록했습니다.

## Result
공개 글은 주사율 차이와 무관하게 일정한 속도를 유지하고 난이도 편차 문제를 해결한 것으로 정리합니다. 이 사례에는 추가로 측정하지 않은 개선 비율이나 벤치마크 수치를 넣지 않습니다.

## Insight
화면이 갱신되는 횟수와 시간이 흐르는 양을 구분해야 합니다. 자세한 코드와 설명은 연결한 원문에서 확인할 수 있습니다.
